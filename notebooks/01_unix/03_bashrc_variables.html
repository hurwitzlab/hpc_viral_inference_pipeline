What is .bashrc

The .bashrc file lives in your home directory (~/) and controls your shell environment. It’s a script that runs automatically every time you open a new terminal session in bash (the Bourne Again SHell). The .bashrc is one of the “dotfiles” in your home directory.

“Dotfiles” are files with names that begin with a dot. They are normally hidden from view unless you use ls -a to list “all” files. A single dot . means the current directory, and two dots .. mean the parent directory. Your .bashrc (or maybe .profile or maybe .bash_profile depending on your system) file is read every time you login to your system, so you can remember your customizations. “Rc” may mean “resource configuration,” but who really knows?

After a while, you may wish to collect your dotfiles into a Github repo.

Contents of .bashrc

$PATH

The $PATHvariable is one of the most important environment variables in Unix/Linux systems, and it is often included in the .bashrc. It tells your shell where to look for executable programs when you type a command.

When you type a command like ls or python, the shell searches through each directory listed in $PATH (in order) until it finds an executable file with that name.

Viewing your PATH

You can view your current PATH with:

echo $PATH

This will show something like:

/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin

Where the directories are separated by colons (:).

Adding to your PATH

To add a new directory to your PATH, add this line to your .bashrc:

export PATH="$HOME/bin:$PATH"

This prepends $HOME/bin to your existing PATH, so the shell will search there first. You can also append to the end:

export PATH="$PATH:$HOME/.local/bin"
Important

Always include $PATH in your new assignment, or you’ll lose access to all the standard system commands!

Common PATH additions

# Add local bin directories
export PATH="$HOME/bin:$HOME/.local/bin:$PATH"

# Add conda/miniconda
export PATH="$HOME/miniconda3/bin:$PATH"

# Add custom software
export PATH="/opt/custom-software/bin:$PATH"

Aliases

Sometimes you’ll find you’re using a particular command quite often and want to create a shortcut. You can assign any command to a single “alias” like so:

alias cx='chmod +x'
alias up2='cd ../../'
alias up3='cd ../../../'

If you execute this on the command line, the alias will be saved until you log out. Adding these lines to your .bashrc will make it available every time you log in. When you make a change and want the shell to bring those into the current environment, you need to source the file. The command . is an alias for source:

$ source ~/.bashrc
$ . ~/.bashrc

Useful aliases

# Navigation shortcuts
alias ..='cd ..'
alias ...='cd ../..'
alias home='cd ~'

# List variations
alias ll='ls -lh'
alias la='ls -lah'
alias l='ls -CF'

# Safety nets
alias rm='rm -i'    # The -i flag stands for "interactive" mode. 
alias cp='cp -i'    # It makes the command ask for confirmation before 
alias mv='mv -i'    # doing anything destructive.

# Git shortcuts
alias gs='git status'
alias ga='git add'
alias gc='git commit'
alias gp='git push'

# Show PATH in readable format
alias path='echo $PATH | tr ":" "\n"'

Shell Functions

Functions are like aliases but more powerful - they can take arguments and contain multiple commands.

Basic function syntax

# Simple function
greet() {                   # Function name followed by ()
    echo "Hello, $1!"       # Function body: $1 is the first argument passed to the function  # Closing brace ends the function
}

# Usage: greet Mery
# Output: Hello, Mery!

Useful function examples

# Create directory and cd into it
mkcd() {
    mkdir -p "$1" && cd "$1"
}

# Backup a file with timestamp
backup() {
    cp "$1" "$1.backup.$(date +%Y%m%d_%H%M%S)"
}

# Extract various archive types
extract() {
    if [ -f "$1" ]; then
        case "$1" in
            *.tar.gz)  tar xzf "$1"    ;;
            *.zip)     unzip "$1"      ;;
            *.tar)     tar xf "$1"     ;;
            *.gz)      gunzip "$1"     ;;
            *)         echo "Unknown archive format" ;;
        esac
    else
        echo "File not found: $1"
    fi
}

# Find files by name
ff() {
    find . -type f -iname "*$1*"
}

Environmental Variables

Environment variables are named values that affect how programs behave. They’re available to all programs run from your shell.

Setting variables

# Set a variable (no spaces around =)
MY_VAR="some value"

# Export to make it available to child processes
export MY_VAR="some value"

# Or in two steps
MY_VAR="some value"
export MY_VAR

Common environment variables

# Home directory
echo $HOME

# Current user
echo $USER

# Current shell
echo $SHELL

# Editor preference
export EDITOR=vim

# Language/locale settings
export LANG=en_US.UTF-8

Using variables in scripts

# Reference a variable with $
echo "My home directory is $HOME"

# Use curly braces for clarity
echo "File: ${filename}.txt"

# Default values
echo "Name: ${NAME:-Anonymous}"

Tips and Best Practices

  • Backup your .bashrc before making major changes
  • Test changes by sourcing the file: . ~/.bashrc
  • Comment your code so you remember what customizations do
  • Organize logically with sections for PATH, aliases, functions, etc.
  • Check for errors with bash -n ~/.bashrc (syntax check without executing)
  • Keep it simple - don’t over-complicate your configuration

Key Takeaways

  • Configuration persistence: The .bashrc file runs automatically at login and stores your shell customizations
  • PATH variable: How the shell finds executable programs and how to add directories to your $PATH
  • Aliases: Creating command shortcuts for frequently used operations
  • Shell functions: Writing more complex custom commands that accept arguments and contain multiple steps
  • Environment variables: Setting and using variables that affect program behavior across your shell session
  • Sourcing files: Applying .bashrc changes to your current session without logging out
  • Best practices: Backing up configurations, commenting code, and testing changes safely

These skills allow you to create a personalized, efficient command-line environment tailored to your workflow. Whether you’re adding bioinformatics tools to your PATH, creating shortcuts for complex pipelines, or setting environment variables for specific software, mastering .bashrc customization is essential for productive terminal use.

Part 1: Understanding Your Current Setup

1. Examine your current configuration:

  • Use cat or less to view your current .bashrc file
  • Identify any existing aliases or PATH modifications
  • Take note of what’s already configured

2. Explore your PATH:

  • Display your current $PATH variable
  • Identify which directory contains the ls command (Hint: use which ls)

3. Test environment variables:

  • Print the values of $HOME, $USER, and $SHELL
  • Create a temporary variable called TEST_VAR with the value “Hello” and echo it
  • Try to access TEST_VAR in a new terminal window - what happens? Why?

Part 2: Creating Custom Aliases

1. Create navigation aliases:

  • Add an alias called proj that navigates to your main project directory
  • Create an alias h that shows your command history
  • Make an alias ports that shows all listening network ports (use netstat or lsof)

2. Create safety aliases:

  • If not already present, add the interactive flags (-i) to rm, cp, and mv
  • Create an alias saferm that moves files to a trash directory instead of deleting them

3. Create information aliases:

  • Make an alias diskspace that shows disk usage in human-readable format
  • Create an alias myip that displays your IP address
  • Add an alias weather that fetches weather for your location (use curl wttr.in/YourCity)

Part 3: Writing Shell Functions

1. Create a directory navigation function:

  • Write a function called mkcd that creates a directory and immediately changes into it
  • Test it by creating a new directory called test_function

2. Create a file finding function:

  • Write a function called findname that searches for files by name in the current directory and subdirectories
  • It should accept one argument (the filename pattern to search for)
  • Example usage: findname "*.txt" should find all text files

3. Create a compression function:

  • Write a function called tardir that takes a directory name and creates a compressed tar.gz archive of it
  • The archive should be named directoryname_YYYYMMDD.tar.gz with today’s date Example: tardir mydata creates mydata_20241204.tar.gz

Part 4: PATH Management

1. Add a custom bin directory:

  • Create a directory called bin in your home directory
  • Add this directory to your PATH in .bashrc
  • Source your .bashrc and verify the directory is in your PATH

2. Create a custom script:

  • In your new ~/bin directory, create a script called hello that prints “Hello from my custom PATH!”
  • Make it executable (chmod +x ~/bin/hello)
  • Verify you can run hello from any directory without specifying the full path

Part 5: Environment Variables

1. Set up bioinformatics environment variables:

  • Create an environment variable called DATA_DIR that points to a directory where you store datasets
  • Create an environment variable calledSCRIPTS_DIR for your analysis scripts
  • Add these to your .bashrc and test them

2. Configure a default text editor:

  • Set the EDITOR environment variable to your preferred text editor (nano, vim, or emacs)
  • Test it by running echo $EDITOR
