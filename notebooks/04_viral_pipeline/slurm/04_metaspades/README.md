# 04: Read assembly with MetaSPAdes
=================
This directory contains scripts and configuration files to run metaSPAdes on clean sequencing reads as part of a viral inference pipeline using a SLURM job scheduler.

The launcher script `run_metaspades.sh` submits a job array to the SLURM scheduler, where each job in the array processes a different sample from the input list through the `04_metaspades.slurm` job script. The configuration file `config.sh` allows you to set parameters such as the input list of samples, working directory, and paths to necessary containers and pass them on to the launcher and the job script.

## Files in this directory
- `run_metaspades.sh`: This is the main launcher script that submits the job array to the SLURM scheduler.
- `04_metaspades.slurm`: This is the SLURM job script that runs metaspades on the raw sequencing reads for each sample.
- `config.sh`: This configuration file allows you to set parameters such as the input list of samples, working directory, and paths to necessary containers.

## How to use these scripts
1. Modify the `config.sh` file to set the appropriate paths and parameters for your analysis.
2. Run the `run_metaspades.sh` script to submit the job array to the SLURM scheduler.
3. Monitor the job status using SLURM commands (e.g., `squeue`, `sacct`, etc.) to check the progress of the metaspades analyses.

## Prerequisites
- Access to an HPC cluster with SLURM job scheduler.
- Apptainer/Singularity installed on the cluster.
- metaSPAdes container available on the cluster.
- Paired reads cleaned with trimmomatic files available in the specified working directory.

## Output
The metaSPAdes assembly results for each sample will be saved in the specified output directory within the working directory. Each sample will have its own subdirectory containing the assembled **contigs** and related files.

This is a list of the main output files generated by metaSPAdes:
metaSPAdes stores all output files in `<output_dir>`, which is set by the user.

- `<output_dir>/corrected/ `directory contains reads corrected by BayesHammer in *.fastq.gz files; if compression is disabled, reads are stored in uncompressed *.fastq files
- `<output_dir>/scaffolds.fasta` contains resulting scaffolds (recommended for use as resulting sequences)
- `<output_dir>/contigs.fasta` contains resulting contigs
- `<output_dir>/assembly_graph_with_scaffolds.gfa `contains SPAdes assembly graph and scaffolds paths in GFA 1.2 format
- `<output_dir>/assembly_graph.fastg` contains SPAdes assembly graph in FASTG format
- `<output_dir>/contigs.paths `contains paths in the assembly graph corresponding to contigs.fasta (see details below)
- `<output_dir>/scaffolds.paths` contains paths in the assembly graph corresponding to scaffolds.fasta (see details below)

## About metaSPAdes
metaSPAdes is a metagenomic assembler designed to assemble genomes from metagenomic sequencing data. It is part of the SPAdes genome assembler toolkit and is optimized for handling complex metagenomic datasets. For more information, visit the [metaSPAdes documentation](https://ablab.github.io/spades/running.html).

Other assemblers that can be used for metagenomic assembly include MEGAHIT and IDBA-UD. Read more about how these assemblers compare for viromics pipelines in this [review article](https://peerj.com/articles/3817/).

### Parameters used in this pipeline:
```bash
apptainer exec ${METASPADES_SIF} metaspades.py \
    --meta \
    -1 ${IN_DIR}/${SAMPLE}_R1.fastq.gz \
    -2 ${IN_DIR}/${SAMPLE}_R2.fastq.gz \
    -o ${OUT_DIR}/${SAMPLE}_metaspades_output \
    -t 16 \
    -m 64 \
    --min-contig-length 2000 \
    -k 21,33,55,77,99,127
```


- `--meta`: This flag indicates that the assembly is being performed on metagenomic data, allowing metaSPAdes to optimize its algorithms for such datasets.
- `-1` and `-2`: These options specify the input files for paired-end reads. `-1` is used for the forward reads file, and `-2` is used for the reverse reads file.
- `-o`: This option specifies the output directory where the assembly results will be saved.
- `-t`: This option sets the number of threads to be used for the assembly process, allowing for parallel processing and faster execution. Default is set to 16 threads.
- `-m`: This option sets the maximum amount of memory (in gigabytes) that metaSPAdes can use during the assembly process. Default is set to 64 GB.
-   : Minumum contig length: 2000 bp
- `-k`: This option specifies the k-mer sizes to be used during the assembly process. In this case, k-mer sizes of 21, 33, 55, 77, 99, and 127 are used to capture a range of sequence overlaps for better assembly quality.
- `--min-contig-length`: This option sets the minimum length for contigs to be included in the final assembly output. Contigs shorter than this length will be discarded. In this case, contigs shorter than 2000 base pairs will not be included in the final results.
